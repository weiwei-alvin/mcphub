# T-004：編輯既有 MCP 並持久生效

**Status:** IN_PROGRESS — 目前工作版本已加入編輯流程；正式 acceptance 尚未完成。
**Blocked by:** T-003
**Type:** 使用者功能垂直切片

## 需求追溯

- Scope：S-02。
- User Stories：US-03。
- PLAN 驗收：AC-02、AC-05。
- 技術查證：無新增；沿用前置的設定機制。
- 原始行為定義以 SPEC.md 為準，不擴張 PLAN.md 範圍。

## What to build

從管理頁修改指定服務的連線資料，套用後真實呼叫使用新資料，其他服務不受影響。

只修改本次測試建立的服務，不修改 T-001 的固定連線樣本。

本張包含交付此結果所需的 UI、業務邏輯、介面、資料保存、輸入驗證與測試。不得把必要的驗證或錯誤處理延到後續工單。

## Acceptance criteria

- [ ] 以已存在 HTTP 測試服務為目標，編輯為回傳不同已知結果的第二個安全測試端點。
- [ ] 套用及重新載入後資料保持更新，Gateway 工具结果與新端點一致。
- [ ] 未修改的另一服務仍可呼叫。
- [ ] 無效編輯被拒絕，原有效設定保留。

## 自動驗證

Golden Path step：AT-004。在專案根目錄執行：

```powershell
python -B tests/acceptance/check.py --ticket T-004
```

新增一對測試服務，將 HTTP 端點編輯為 replacement_http fixture；重載及實際呼叫必須取得不同的新預期結果，另一服務仍成功。

實際程式位於 tests/acceptance/check.py；操作契約、fixture 與環境需求見 tests/acceptance/README.md。環境未就緒時回傳非零，不跳過、不輸出假成功。此命令只涵蓋明列的自動檢查，不代表整張工單全部通過。

## 必要補充驗證

補測無效編輯、錯誤欄位與既有服務不中斷的行為。

審查者必須逐項核對未被上述自動命令涵蓋的 Acceptance criteria，提供實際來源與限制。僅有自動 PASS 或證據欄位完整，均不足以完成工單。

## 完成與交接

- [ ] 工單限定的自動命令通過，實際輸出及版本可追溯。
- [ ] 全部人工及負向驗收完成；未測不得填 PASS。
- [ ] 技術選擇與查證結果可供下一張沿用，機密不進文件或日誌。
- [ ] 保留測試環境重現方法；明列修改與需清理的測試資源，不自行清理正式服務。
- [ ] 由實際 harness 流程記錄驗證與審查；本文件不代替 runtime state。
