## What to build

檔案工具只操作使用者明確指定的資料夾，範圍外操作遭實際拒絕。

僅使用自建測試資料；啟用真實檔案工具前確立限制。

本張包含交付此結果所需的 UI、業務邏輯、介面、資料保存、輸入驗證與測試。不得把必要的驗證或錯誤處理延到後續工單。

## Acceptance criteria

- [ ] 先限定專用測試資料夾；擴充範圍需使用者明確操作。
- [ ] 範圍內的安全工具操作成功。
- [ ] 範圍外讀寫被執行端或下游拒絕且樣本不變。
- [ ] 測試路徑穿越及連結等繞過方式；不以提示詞或畫面宣告代替限制。

Golden Path step：AT-009。在專案根目錄執行：

```powershell
python -B tests/acceptance/check.py --ticket T-009
```

透過實際 Gateway 執行 allowed、outside、traversal 與 symlink 四組檔案工具請求；核對成功內容、每組明確權限拒絕及範圍外哨兵檔雜湊不變。fixture 必須宣告允許資料夾位於隔離根目錄內。

實際程式位於 tests/acceptance/check.py；操作契約、fixture 與環境需求見 tests/acceptance/README.md。環境未就緒時回傳非零，不跳過、不輸出假成功。此命令只涵蓋明列的自動檢查，不代表整張工單全部通過。

## 必要補充驗證

介面加入目錄、穿越、連結、拒絕讀取及拒絕寫入都需另留完整證據；哨兵檔不變不是所有檔案未變的證明。

審查者必須逐項核對未被上述自動命令涵蓋的 Acceptance criteria，提供實際來源與限制。僅有自動 PASS 或證據欄位完整，均不足以完成工單。
